# Optional Lovable mock exploration

Try one small chat design for HelioDesk's equipment dispatcher and keep one useful idea for your Python app. The required project uses the [Streamlit teaching kit](../examples/streamlit/README.md) and can be completed without Lovable. This exploration supplies no required project artifact.

## Choose the free mock or sketch path

Use a personal free account only if available. Check the allowance displayed in your account before building; do not purchase credits. If you cannot or prefer not to use Lovable, sketch the same screen or continue with the supplied Streamlit brief. A failed or unfinished mock does not block your project.

Use only synthetic course examples. No GitHub connection, code export, Node.js, Cloud/Supabase setup, API key or publication is needed. The mock uses fixed replies and calls neither FieldCare nor OpenRouter. ChatGPT remains the coding helper for the required Python app; the running FieldCare application uses OpenRouter.

## Build one small mock, or sketch it

Read the complete [first-build prompt](../examples/lovable/first-build-prompt.txt) before submitting it. If you already have a useful prototype, inspect it first. Do not regenerate working material just to match an example. Stop if building does not finish within your available allowance.

Use the **FieldCare composer inside the app preview** for the checks below. A message to the Lovable builder asks it to do additional work and may consume credits. Decline requests for a database, Cloud setup or AI connection; this exercise only needs local mock replies.

## Inspect the result

Use `Which filter and airflow checks are documented?` and equipment `EQ-FC-1002`.

| Try in the preview or explain in your sketch | Look for |
|---|---|
| Send a question with equipment. | A user message and progressive mock reply; sources and reference are labelled synthetic. |
| Send another question. | Both message pairs remain visible and the composer stays reachable. |
| Clear equipment and send the question. | A request for equipment, distinct from a connection error. |
| After a success, send `DEMO ERROR`. | The earlier success remains; the new error does not reuse its answer or reference. |
| Try an empty or spaces-only question. | Submission is disabled or feedback appears without starting a reply. |
| Inspect a narrow view and use Tab/Shift+Tab. | Text wraps; controls are reachable; the composer does not cover the answer. |

Record what actually happened, including failures and checks you did not try. These observations do not prove that a service or model works. You do not need every case to pass.

Identify whether the observation came from a preview, sketch or demonstration. No project link, account access, export or publication is required.
