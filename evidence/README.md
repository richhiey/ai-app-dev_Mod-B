# Keep evidence another developer can follow

Create `observations.md` here. Keep the record short and tied to your actual run:

1. **Starting state:** repository revision (`git rev-parse HEAD`), your changed files, preserved routes and configured policy. The revision alone does not include uncommitted edits; submit the matching source archive.
2. **Prediction:** caller label, route, body category, expected status and why.
3. **Observation:** actual status, relevant response fields, `Retry-After`, and whether the same server process remained running.
4. **Interpretation:** the boundary explaining the result and what remains unverified.

For Sprint 3 add the actual request ID, event order/terminal outcome, its matching minimized log record, selected Module A case IDs, evaluation results and design hash. Preserve the distinction between delivery, privacy and behavioral evaluation.

Include one supported generated answer and a claim checked against its citation where your assessment requires it. Generated wording varies; expected output is a contract or behavior, not a memorized paragraph.

Keep provider and caller values, complete headers, private prompts and raw unrelated logs out of this folder. The supplied FieldCare inputs are synthetic. Include only selected safe Markdown/JSON evidence; `.env` and `var/` are excluded from the source export. Review the archive before sharing it.

Your lesson's assessment brief determines the required evidence. This template does not supply its solution.
